### 移动端（Expo）怎么在手机上跑
详见 `docs/移动端测试.md`（含测试用例表与排障）。三条命令：
```bash
$env:HOST="0.0.0.0"; node apps/api/src/server.ts   # 后端必须监听 0.0.0.0，手机才连得上
start_mobile.bat                                   # Metro(8081) + Expo Go 扫码
```
- 应用目录 `mobile/`：独立 npm 工程（不参与根 pnpm workspace）。
- 后端地址自动推导：取 Metro 的 IP、端口换成 app.json 的 extra.apiPort(8787)，无需改代码；隧道/远程后端用 `EXPO_PUBLIC_API_URL` 覆盖。
- 手机端认证走 Bearer Token（后端 `/api/login` 支持 `issueToken: true`），因为 React Native 没有浏览器 cookie jar。
- 主题：`packages/themes/tokens.css` → `mobile/src/theme/generated.ts`，8 套主题在 App 内可切换（待办页顶部）。

## D7 · 扫条码录入（2026-09-24 第一版）
- 目标：随手记里的「扫条码」真能用——扫一次认出来，同一个码下次直接带出名字。
- 做法（不依赖任何外部条码源）：**条码当本地字典的键**。第一次扫到不认识的东西，用户填一次名字 → 条码落进 items.barcode；以后同一个码先按条码查，命中就带出名称/单位/上次地点。
- 后端：receiptSchema 加 barcode；stock.findOrCreateItem 的认物品顺序 = itemId → **条码** → 名称；命中已有物品且它本来没有条码时顺手补上（bindBarcode），已有别的条码则不动（避免两个物品抢同一个码）。
- 移动端：expo-camera@~57.0.5（Expo Go 内置，无需 dev build）+ mobile/src/components/ScanBarcode.tsx 全屏取景；mobile/src/lib/barcode.ts 只做字符串归一化与精确匹配（纯函数，可单测）。
- 为什么不做"自动查商品名"：那需要外部条码源（额度/中文覆盖/联网），而「本地字典 + 认错当场改」零依赖、越用越准。
- 验证：cd mobile && npm test → 4 suites / 30 项通过（含"认出已有物品并带条码入库""新条码不瞎编名字"）；node scripts/verify-all.mjs → 9/9，其中 verify-m1.mjs 新增第 10 项「扫同一个条码认出同一物品（不重复建）」。
- 翻案成本：低（要接外部条码源，只是在按条码查不到时加一层兜底）。

## D10 · 输入框必须待在输入法上方（2026-09-24 用户实机反馈）
- 问题：手机弹出输入法后把输入框盖住，用户看不见自己打了什么；用户要求「输入框永远在输入法上方，页面动态让位」。
- 做法（纯 JS，不引入原生库，Expo Go 直接生效）：`mobile/src/lib/keyboard.ts` 的 `keyboardOverlap(keyboardHeight, baseWindowHeight, currentWindowHeight)` = 键盘高度 − 系统已经压缩掉的窗口高度（负数取 0），`useKeyboardOverlap()` 把它做成钩子。
  - 弹层：`components/ui.tsx` 的 `Sheet` 用 `marginBottom: overlap` 整体抬到键盘上方，内部滚动区高度同步变矮（`maxHeight = 520 − overlap`）。
  - 整屏：今日 / 库存 / 待办 / 容器 / 周期家务 / 登录 的滚动容器都加了 `marginBottom: overlap`；`CollapsibleList` 的「显示全部」整屏页同样处理。
- 为什么这么算：Android 有的机型（含 Expo Go）键盘弹起时系统会自己压缩窗口，有的不会；只补差额就不会「又压缩又抬高」出现一大截空白。
- 机器守卫：`mobile/src/__tests__/keyboard-guard.test.ts`（扫 `src/screens`、`src/components`：有 `<TextInput` 的整屏必须接钩子；自己开浮层的组件必须自己避让或渲染在 `Sheet` 里）。**这条守卫第一次跑就抓出了 `CollapsibleList` 的「显示全部」整屏页漏接**——正是这类问题肉眼看代码看不出来。
- 验证：`npx tsc --noEmit` → 0 错；`npm test` → 7 suites / 43 项通过；`node scripts/verify-all.mjs` → 9/9。
- 还没验证：真机上弹层（Modal 里开键盘）是否也能触发键盘事件、抬升是否自然——要用户实机确认；若弹层没反应，改用「输入时把弹层内容换成整屏表单」的写法。
