# 家用仓管 App 开发计划（MVP）

> 版本：v1.0（待确认）
> 依据：docs/灵感来源.txt + docs/可行性探讨报告.md + AL1S-WMS 参考实现实测
> 说明：UI 设计稿由用户另行安排设计；本计划只管功能、数据与技术实现。
> ⚠️ 2026-09-24 更新：产品形态已定为**只做移动端（Expo）**，本文里 PWA / 网页端 / 浏览器相关的表述均已作废（`apps/web` 已删除）；功能范围与技术栈其余部分仍然有效。

## 1. 目标

做一个**个人/小家庭使用的轻量级"家庭仓管 + 日历 + 待办提醒"App（移动端 Expo）**，核心价值一句话：

> 不只记录"家里有什么、放在哪"，而是告诉你"**今天该吃什么、该买什么、该做什么**"。

**成功标准（MVP 验收，全部可测）：**
- 一条数据链路走通：录入物品（含批次/位置/保质期）→ 自动出现在日历与今日待办 → 临期/缺货提醒 → 采购后一键入库 → 库存与日历同步更新。
- 三条工作流各自在真机 App 上可操作完成，无阻塞性 bug。
- MCP 端点可被标准客户端（如 Cherry Studio）接入并调用核心工具。
- 数据存本地 SQLite 单文件，换机器拷走即恢复。

## 2. 范围

### 做（MVP）
| 模块 | 内容 |
| --- | --- |
| 库存 | 物品（名称/分类/单位/图标/条码）、地点树、批次（生产日期/到期日期/价格）、入库/领用/调拨/盘点、FEFO（先过期先用） |
| 日历 | 一张家庭运营日历，四类事件同屏：临期处理、采购计划、家务待办、用药/到期 |
| 待办提醒 | 周期家务模板（清冰箱/换滤芯）、与库存联动生成待办（滤芯用完→"买+换"两条）、临期生成"吃掉/用掉"待办 |
| 录入 | 手动表单 + 扫条码（✅ 已做：条码优先认物品，本地自建字典，不依赖外部条码源）+ 语音一句话解析（LLM 结构化，待做） |
| 采购闭环 | 缺货自动建议 → 购物清单 → 收货一键入库（沿用 AL1S 模式） |
| MCP | Streamable HTTP 端点 + 家庭级 Token，核心工具可被 Agent 调用 |
| 提醒通道 | MVP：打开 App 可见（今日视图/角标）；推送服务（ntfy/微信/邮件）作为 P1 |

### 不做（写死，防止膨胀）
- 不做：多人 RBAC（单用户/单家庭，但数据模型预留 home_id）
- 不做：专业财务（发票/税费/复式记账/多币种）；只记"花了多少钱"这一层
- 不做：企业 WMS 特性（审批、波次拣货、审计）
- 不做：食谱/膳食计划（与 Mealie/Tandoor 的边界）
- 不做：小程序、网页端/PWA（只做移动端 App）

## 3. 技术栈（我定，理由如下）

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | TypeScript 全栈 | AL1S-WMS 同款且已实测跑通；单语言少心智负担；官方 MCP SDK 是 TS 一等公民 |
| 后端 | Fastify 5 | 轻量、快，AL1S 已验证；够用不过度 |
| 数据库 | Node 24 内置 node:sqlite（零原生依赖）+ 手写 SQL 迁移 | AL1S 实测可行；单文件、零安装、自托管友好 |
| 客户端 | Expo / React Native（只做移动端） | 用户 2026-09-24 明确只做移动端；Expo Go 真机流程已跑通 |
| MCP | @modelcontextprotocol/sdk（Streamable HTTP） | AL1S 实测 46 工具全部可用 |
| LLM | 语音/小票结构化：接兼容 OpenAI 接口的模型（DeepSeek 等），key 由用户配置 | 本地不留云依赖，无 key 时降级为手动录入 |
| 部署 | pnpm + Docker（单容器 + SQLite volume） | 一条命令跑起来 |

**说明**：工作区目录名含 python 但用户明确与技术栈无关；TS 全栈是本项目最优解。参考实现已保留在 reference/AL1S-WMS，开发中可随时对照。

## 4. 数据模型（核心表，参考 AL1S 实测 schema 并做加减）

- homes（家庭，单家庭 MVP 也保留）
- locations（地点树：冰箱/储物柜/药箱…）
- item_categories（分类树）
- items（物品：名称/单位/分类/默认地点/补货阈值/消耗类型）
- stock_batches（批次：生产日期/到期日期/价格/渠道，**临期与财务都挂这里**）
- stock_transactions（流水：入库/领用/调拨/盘点，幂等键）
- shopping_list（购物清单：含自动补货建议与采购日历的 planned_date）
- tasks（**新增：待办**——周期家务/库存联动/临期处理，含 due_date、来源类型、完成状态）
- item_events（物品事件史，保留审计）
- api_tokens / sessions / users（沿用 AL1S 认证模式）

与 AL1S-WMS 的差异：**砍掉** finance_budgets 全家桶（预算/趋势/成本分析 P2 再说）、opened_consumables 简化掉；**新增** tasks 表与提醒逻辑；**保留**批次/流水/购物清单/日历索引。

## 5. 功能拆解与优先级

**P0（MVP 必须，两周）**
1. 骨架：项目脚手架 + SQLite schema + 认证/初始化 + 基础布局（中性样式，等设计稿）
2. 库存核心：物品/地点/分类 CRUD + 入库/领用/调拨/盘点 + 批次与 FEFO
3. 日历：四类事件聚合查询 + 月/今日视图
4. 待办：tasks 表 + 周期家务模板 + 库存联动（低库存→购买待办、临期→处理待办）
5. 采购闭环：购物清单 + 收货入库（一条请求生成批次+流水+完成清单）
6. MCP：get_home_overview / search_items / record_receipt / 待办与日历工具（约 20 个核心工具，不追求 AL1S 的 46 个）
7. 提醒：今日视图角标（临期/待办到期）

**P1（有设计稿后/二周后）**
- 语音一句话录入（LLM 结构化，失败可手动改）
- 拍小票 OCR 录入（多件一次入）
- 推送通道：ntfy / 邮件（自托管友好）
- 条码查询（ApiZero，AL1S 已验证）

**P2（不承诺）**
- 预算/支出统计（只记不分析）
- 多家庭切换
- 导入导出

## 6. 里程碑（每步有可验证产物）

| 里程碑 | 内容 | 验证方式 |
| --- | --- | --- |
| M0 骨架（1-2 天） | 脚手架 + DB + 初始化 + 空页面 | 启动后完成初始化，healthz 200 |
| M1 库存核心（3-4 天） | 物品/批次/流水/盘点 | 手动走完"建物品→入库→领用→盘点"，数字正确 |
| M2 日历+待办（3-4 天） | 四类事件聚合 + tasks | 临期物品自动出现在日历；勾选待办完成 |
| M3 采购闭环+MCP（2-3 天） | 购物清单/收货/MCP 工具 | MCP 客户端调 get_home_overview 返回正确预警 |
| M4 提醒+验收（2-3 天） | 角标提醒 + 全链路回归 | 按第 1 节成功标准逐条验收 |

总计约 2 周（与实际可用时间无关，是工作量估计，可能因设计稿接入时间而变）。
